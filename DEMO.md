# DEMO.md — the interview demo

Format per the brief's Demo Day: **Part 1 — Live Demo, ~9 min** (scripted beats end at 8:00, leaving a full 1 min slack), **Part 2 — Live Walkthrough & Decision Review, 7–10 min**, then **5 min Q&A** ([docs/qa-prep.md](docs/qa-prep.md)).

Everything opens on the **site root** — **https://noc-edge-41d2a334-7.telnyxcompute.com/** (`/demo` serves the same page). Every call can be a browser web call from the page, or a real call to the public line **+1 512 980 6105** (a US number; international from KSA). The **operator console is hidden**: press the backtick key or append `#console` (scenarios + the two demo PINs, detailed board, event feed, presenter controls). All commands read `.env` (`EDGE_URL`, `OPS_TOKEN`); `scripts/ops.mjs` never echoes the token. `$KV_ID` is the `noc-kv` namespace id (`telnyx-edge storage kv list` — runbook fault-drill preamble). The external prober must be running (runbook §6): it heals the KV projections and claims/sends alarm pages every 30 s.

**Pre-flight (5 minutes before, not during):** screen recording on; prober output, the invocation log (`telnyx-edge logs noc-edge --tail --type invocations`) and `/ops/status` open side by side — that is the observability surface for the whole demo. Reset + stage are a scripted beat below (the DV/flag beat needs them done in a specific order).

## Part 2 — Live Walkthrough & Decision Review (7–10 min)

One row per the brief's prompts, ~45–60 s each — open the anchor, make the point, move on.

| Brief prompt | The answer + anchor |
|---|---|
| Why this use case | A regional outage makes every affected branch call separately — the queue fills with duplicates and the SLA clock runs while humans de-duplicate. Sanad verifies → de-duplicates → escalates P2→P1 at the third branch → pages if unacknowledged. Anchor: [README.md](README.md) "What it is". |
| How the Conversation Workflow is structured | `assistant/assistant.json` — 25 nodes (11 speak · 8 prompt · 6 tool), 61 edges (19 expression · 26 llm · 16 default), start `s_open`; speak nodes carry every verbatim line (disclosure, advisory, read-backs, the Arabic bridge `s_to_ar`); every prompt node has a human-request exit and an Arabic exit (`requireArabicExits` in `scripts/lib/flow-validate.mjs`). Arabic: `assistant-assistant-ar.json` — 16 nodes (4 speak · 6 prompt · 6 tool), 37 edges, start `s_ar_open` routing by carried state. Anchor: [docs/walkthrough.md](docs/walkthrough.md) stop 1; Portal canvas if asked. |
| How the MCP server is structured | `edge/noc-edge/src/mcp/server.ts:141` (`handleMcp`), `mcp/tools.ts:345` (`registerMcpTools` — the 5 tools with zod schemas), `mcp/shim.ts` (two bearer scopes: `session` resolves the caller from the conversation, `ops` cannot touch sessions). C4: stateless, POST-only, a fresh server + transport per request, GET → 405. The Arabic catalog (`/mcp?lang=ar`) is built and tested but detached for the demo — with it attached the EN→AR handoff took 40–80 s vs ~10 s detached (DEBUGLOG #22). Anchor: [docs/walkthrough.md](docs/walkthrough.md) stop 7. |
| How Dynamic Webhook Variables are used | `edge/noc-edge/src/dv/handler.ts:145` — Ed25519-signed, fail-open within the 2500 ms budget, concurrent KV; returns personalisation (`caller_name`, `site`, `incident_*`, `open_ticket_note`) and `route_hint`, which drives the opening expression edges (unverified → PIN, known_incident → advisory, arabic → handoff). Anchor: [docs/walkthrough.md](docs/walkthrough.md) stop 2; the live beat at 4:05. |
| Why Actors vs KV vs plain function logic | Actors own every invariant (serialized turns = locks for free; race test: 10 opens → 1 ticket); KV is only projection / cache / flags — one writer per key, healed by the prober; plain function logic holds nothing durable across requests. Cloud Storage holds resolved-incident reports; the page's sessionStorage holds the operator's token. Anchor: [docs/decisions.md](docs/decisions.md) state→primitive table + #2. |
| How Telnyx Inference via OpenCode was used + model choice | `opencode.jsonc` — plugin `@telnyx/opencode@0.1.5`; GLM-5.3-Flash for mechanical implementer lanes, GLM-5.3 for design/prose, one Kimi-K3 lane (the KV-free fix). 89 of 112 commits as of `e6c9772` carry `Assisted-by: OpenCode`; the exceptions are disclosed (spec/plan authorship, the page visual layer, one revert). Anchor: [DOGFOODING.md](DOGFOODING.md) + cost table. |
| How you found the hardest bug — the signal | Two stories: (a) call #1 — the trace showed `verify_site` **7869 ms** against a 5000 ms timeout → sequential KV was the cause → concurrent KV (DEBUGLOG #6/#8); (b) the 09-28 outage — a brand-new actor id, the host's own increment and direct KV REST all failed → platform; paged log windows found ~4,000 KV failures where one page showed 94 (DEBUGLOG #15). The signal chain: `trace.sh` → invocation log → paged logs. Anchor: [DEBUGLOG.md](DEBUGLOG.md) #15, #19. |
| Tradeoffs you considered | LLM vs expression edges; append vs replace instructions; mux vs per-entity; the actor as PIN authority vs KV auth; in-process MCP vs a second function; Arabic MCP attached vs detached; presigned URLs rejected for reports. Anchor: [docs/decisions.md](docs/decisions.md) — 19 rows with alternatives and cost-if-wrong. |
| How edge cases and errors are handled | Fallback paths proven on live calls: #1 (verify timeout → transfer → take message → callback), #5 (actors down → `s_verify_unavailable` → message). Signed routes fail closed (403), unproven writes get a uniform 403, PIN tiers lock the call then the site, `/dv` fails open, Arabic exits from every node, mandatory actions are tool nodes. Anchor: [DEBUGLOG.md](DEBUGLOG.md) #16, #19, #20; [docs/qa-prep.md](docs/qa-prep.md). |
